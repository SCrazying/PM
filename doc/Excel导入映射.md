# Excel 台账导入 · 字段映射与解析规则

| 项目代号 | PM-System |
|---|---|
| 文档版本 | V1.0 |
| 编制日期 | 2026-08-02 |
| 依据文档 | 策划书 V2.3 / 架构设计文档 V1.2（§7 import、§9.5） |
| 关联接口 | `POST /import/excel/preview`、`POST /import/excel/confirm` |

> 本文定义**现有组内 Excel 周报表**如何映射进系统，供 Excel 导入功能（preview/confirm 两步）实现。导入以"**项目/节点/任务骨架 + 当前周目标**"为主；历史进展迁移见 §6（默认不迁，可选）。

---

## 1. 现有 Excel 结构回顾

组内周报表（以"人"为行）表头：

| 机型 | 项目 | 是否投入该项目 | 项目角色 | 关键节点 | 项目周目标 | 本周任务 | 每日任务 |
|---|---|---|---|---|---|---|---|

特点：**一行 = 某成员在某项目本周的投入与任务**；同一项目跨多行（多人）、同一人也可能跨多行（多项目）；每日任务通常挤在一个单元格内。

---

## 2. 导入总策略

导入是**"以项目为轴的汇聚"**：把按人分散的行，按"项目"归并，重建系统的四层结构（项目 → 节点 → 任务）+ 成员 + 周目标。

| Excel 列 | 系统落点 | 处理方式 |
|---|---|---|
| 机型 | `project.machine_model` | 同项目多行取首个非空值 |
| 项目 | `project.name` / `project.code` | 项目名→name；code 自动生成或取自映射表 |
| 是否投入该项目 | `project_member.is_invested` | 是/否 → true/false |
| 项目角色 | `project_member.project_role` | 直接落；"负责人"行同步 project.owner_id |
| 关键节点 | `project_node`（当前节点） | 文本匹配 TR 节点（见 §4 节点映射） |
| 项目周目标 | `project_weekly_goal.goal` | 归入**导入当周**的 week_start |
| 本周任务 | `task`（挂当前节点） | 按行/按分隔拆成任务 |
| 每日任务 | 默认**不导入**（流水，见 §6） | 可选：汇总为一条进展 |

> 成员（人名）→ `user`：按 display_name 匹配已有用户；不存在则按策略创建或跳过（见 §5）。

---

## 3. 逐列映射细则

### 3.1 项目（机型 / 项目）
- **归并键**：`机型 + 项目名` 判定为同一项目（去重多行）。
- `project.name` = 项目列文本（trim）。
- `project.machine_model` = 机型列文本。
- `project.code`：优先取"项目代号映射表"（可上传第二 sheet 或配置）；缺省自动生成 `P + 年份 + 序号`，导入后可改。
- `project.status`：默认 `in_progress`（导入的均为在研）；可在预览时逐项目调整。
- `project.start_date/end_date`：Excel 无此列 → 留空，导入后补。

### 3.2 成员（是否投入 / 项目角色）
- 每个"项目+人"组合生成一条 `project_member`。
- `project_role` = 项目角色列原文（负责人/开发/测试…）。
- `is_invested` = 是否投入列：是/Y/√/1 → true；否/N/空 → false。
- **负责人识别**：角色含"负责人/PM/Owner"（可配置关键词）的成员 → 设 `project.owner_id`，并保证其在 `project_member` 中（架构约束）。一个项目识别到多个负责人时，预览阶段提示人工选一个。

### 3.3 关键节点（→ 当前 TR 节点）
Excel"关键节点"是自由文本（如"TR3""需求评审""开发中"），需映射到标准节点：

| Excel 文本（示例） | 映射 project_node | 规则 |
|---|---|---|
| TR1 / 需求评审 / 概念 | TR1 | 关键词匹配 |
| TR2 / 方案 / 计划 | TR2 | 同上 |
| TR3 / 设计 / 开发前 | TR3 | 同上 |
| TR4 / 开发 / 编码 / 测试 | TR4 | 同上 |
| TR5 / 发布 / 验证 | TR5 | 同上 |
| TR6 / 收尾 / 量产 | TR6 | 同上 |
| 无法识别 | 预览标黄，人工指定 | 兜底 |

- 导入时按所选模板（默认标准 TR1~TR6）**实例化全部节点**，把"当前节点"置为匹配到的节点：
  - 该节点之前的节点 → status=`passed`（actual_end 留空）；
  - 当前节点 → status=`in_progress`；
  - 之后节点 → status=`not_started`；
  - 维护 `project.current_node_id`。
- 若项目只需部分节点（立项自选），预览时可勾选，默认全量。

### 3.4 项目周目标
- 取该项目**最新一行**（或合并去重）的周目标文本 → `project_weekly_goal.goal`。
- `week_start` = **导入当周周一**（按 config `report.week_start_dow` 规整）。
- 同项目多行周目标不一致 → 预览列出，人工选择/合并。

### 3.5 本周任务（→ task）
- 单元格内多个任务按分隔符拆分：**换行 / ；/ 、 / 数字序号**（可配置）。
- 每条生成一个 `task`：`project_node_id` = 当前节点；`title` = 任务文本；`assignee_id` = 该行人；`status` = `in_progress`（默认，预览可改）；planned/actual 时间留空。
- 同一任务被多人提及 → 默认各建一条（指派给各自），预览可合并。

### 3.6 每日任务（→ 默认不导入）
- "每日任务"是历史流水，**默认不导入**（策划书 §16-5 默认只迁骨架）。
- 可选开关：若开启"导入最近一周每日任务"，把该单元格文本汇总为**一条项目级进展**（`progress`：author=该行人、progress_date=导入当天、today_work=原文），仅作衔接，不做逐日拆分。

## 4. 解析与校验规则（preview 阶段）

preview 接口解析后返回**结构化预览 + 校验结果**，不落库：

| 校验 | 级别 | 处理 |
|---|---|---|
| 机型/项目名为空 | 错误 | 该行拒绝，提示 |
| 项目无法识别负责人 | 警告 | 预览标黄，人工指定 |
| 关键节点无法映射 | 警告 | 标黄，人工选择节点 |
| 人名无法匹配 user | 警告 | 选择"创建用户/跳过该行/映射到指定用户" |
| 周目标/任务为空 | 提示 | 允许，导入后补 |
| 同项目多行周目标冲突 | 警告 | 列出，人工合并 |
| 项目 code 冲突（已存在） | 处理 | 提示"更新已有项目 / 新建"，默认更新 |

预览返回：`{ projects: [{ name, machine_model, owner, members[], current_node, weekly_goal, tasks[] }], warnings[], errors[] }`。

## 5. 用户匹配策略
- 优先按 `user.display_name` 精确匹配（忽略空格/大小写）。
- 匹配不到 → 三选一（预览时逐人选）：
  1. **创建新用户**：username 自动生成（拼音/工号，需映射表），默认密码首登强制改；
  2. **映射到已有用户**（纠正 Excel 里的昵称/别名）；
  3. **跳过**：该行成员不导入（任务/进展也不挂）。
- 别名映射表可作为配置持久化，下次导入复用。

---

## 6. 历史数据迁移范围（默认）
| 数据 | 默认 | 说明 |
|---|---|---|
| 项目/节点/任务骨架 | ✅ 导入 | 核心 |
| 成员/角色/是否投入 | ✅ 导入 | 核心 |
| 当前周目标 | ✅ 导入 | 归入当周 |
| **历史每日进展** | ❌ 不导入 | 流水，保留在原 Excel 存档即可 |
| 历史周目标/历史节点时间 | ❌ 不导入 | 无法可靠还原 |

> 若后续确需迁历史进展，沿用 preview/confirm 两步 + 进展表唯一约束（一人一天一项目/节点一条）即可，本文已预留 §3.6 开关。

---

## 7. 幂等与确认（confirm 阶段）
- confirm 携带 `Idempotency-Key`（前端生成 UUID），重复提交/重试只入库一次。
- 按"项目 code 或 机型+项目名"判定：已存在 → **更新**（合并成员/任务，更新当前节点与周目标）；不存在 → **新建**。
- 整个 confirm 在一个**事务**内；任一项目失败回滚该项目并汇总到结果（成功 N / 失败 M + 原因）。
- 导入完成写 `audit_log(action=import, detail=导入摘要)`。

---

## 8. 导入模板（供用户下载的标准格式）
建议提供一个标准导入模板（比现有自由表更规整，降低解析歧义），列：

| 机型 | 项目 | 项目代号(可选) | 负责人 | 成员(角色,逗号分隔) | 是否投入 | 当前TR节点 | 周目标 | 本周任务(换行分隔) |
|---|---|---|---|---|---|---|---|---|

> 同时兼容解析**现有自由格式**（§3），标准模板作为推荐。两种格式都走 preview/confirm。
