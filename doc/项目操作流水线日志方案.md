# 项目操作流水线日志方案（V1.0.5）

## 1. 需求目标

在**项目维度**提供一份完整的"操作流水账"（时间线）：项目负责人/成员在项目详情里能查看到该项目发生过的关键操作历史，例如：

- 项目创建、编辑（哪些字段改了：名称/编号/机型/状态/负责人/起止日期等）
- 节点计划完成时间修改（谁在什么时候把 TR3 的完成日期从 08-06 改到 08-13）
- 周目标设置与条目变更（添加目标、完成/取消、调整归属周次）
- 成员与角色变更、任务增删改、进展填报、风险上报、附件上传/删除
- 节点流转与评审（送审、通过、打回、强制流转、直接完成）

现状缺口：系统已有全局操作审计（audit_log，V1.0.4），但只有管理员能查（`/admin/audit-logs`），且按操作者/动作/对象维度过滤，**没有"某个项目发生了哪些事"的项目视角**，普通成员也无法查看。

## 2. 现状分析（audit_log 已有能力）

| 事实 | 说明 |
|---|---|
| 写操作全覆盖 | 58 个写接口均已 `record_audit`（action: create/update/delete/restore/purge/review/transition/force_transition/backup/import/login/logout 等） |
| 项目级操作 | `target_type=project/member/project_risk/weekly_goal`，target_id 即 project_id，天然按项目可查 |
| 节点/任务级操作 | `target_type=node/task`，target_id 是节点/任务 id，**detail 中未带 project_id**，需 join 表解析归属 |
| 变更内容 | 编辑类操作 detail 存字段前后 diff（audit_service `diff_dict`）或提交体快照 |
| 保留期 | 默认 24 个月，按天分批清理（`_audit_cleanup_loop`） |

结论：**数据已齐全，缺的是"项目视角"的查询与展示**，不需要新建表、不需要双写。

## 3. 方案对比

| 方案 | 说明 | 表结构变更 | 历史数据 | 工作量 | 评价 |
|---|---|---|---|---|---|
| A. 复用 audit_log + 项目视角接口 | 新接口按项目聚合 audit_log：项目直系记录 + 节点/任务等通过 join 解析归属；detail 翻译为中文动作 | 无（零迁移） | 立即可用 | 小 | **推荐** |
| B. 新表 project_activity 双写 | 每操作写两条日志 | 需迁移 0015 | 无（上线后才有） | 大 | 与 audit_log 冗余，不取 |
| C. audit_log 加 project_id 列 | 迁移 0015 + 58 处调用补参 + 回填 | 需迁移 0015 | 需回填脚本 | 中 | 查询最优，但动表，V1.0.5 不必 |

**推荐方案 A**，理由：
1. 用户红线"数据库兼容性"——方案 A 零表结构变更、零迁移，无任何兼容风险
2. audit_log 已全量覆盖，双写/加列均属冗余工程
3. 查询接口按 target_type 分路 join（project_node/task 表取 project_id），项目数在组内规模（数十个）下性能无压力，可后续按需加索引
4. 未来若项目流水线查询量变大，再做方案 C 的 project_id 列（迁移 0015）也不迟，接口层无需改动

## 4. 接口设计

### 4.1 查询项目流水线

```
GET /projects/{project_id}/activity-log?page=1&size=20&action=&date_from=&date_to=
```

权限：项目成员 / 负责人 / 管理员（复用 `ProjectService.check_member`；项目不存在或非成员 → 403/404）。

归属解析（一条 SQL 按 type 分路）：

| target_type | 归属方式 |
|---|---|
| project / member / project_risk / weekly_goal / weekly_goal_item / attachment / machine_model | target_id 直接为 project_id，或 detail 中 project_id |
| node | audit target_id → `project_node.project_id` |
| task | audit target_id → `task.project_id` |
| ai_summary / user / config / audit_log 等非项目操作 | 不进入项目流水线 |

返回项：

```json
{
  "id": 123, "time": "2026-08-13 10:30:00", "actor_id": 3, "actor_name": "张三",
  "action": "update", "action_label": "更新项目",
  "target_type": "node", "target_label": "节点 TR3",
  "detail": { "planned_end": { "before": "2026-08-06", "after": "2026-08-13" } },
  "summary": "张三 修改了节点 TR3 计划完成时间：08-06 → 08-13"
}
```

- `action_label` / `target_label`：复用 m3.py 的 `/admin/audit-meta` 中英文映射，并扩充项目流水线专用文案
- `summary`：后端把 detail 按操作类型渲染成一句中文（如"修改节点计划完成时间""添加周目标条目""新增成员"），前端直接展示
- 分页默认 20/页，上限 100；支持按 action 与日期范围过滤

### 4.2 顺带补齐（不改表）

节点/任务类操作的 `record_audit` detail 中补 `project_id`（transition/advance/review/complete、子节点增删改、任务增删改、附件），为流水线归属解析减少 join 依赖，同时便于将来按项目做聚合统计。

## 5. 前端设计

项目详情页新增「操作流水」页签（或时间线区块）：

- 展示方式：倒序时间线（时间 → 操作者 → 中文动作 → 变更摘要）
- 变更摘要对 diff 类型 detail 高亮"before → after"
- 分页加载；可筛选操作类型（下拉，取自接口返回的 action 集合）
- 复用现有 `AuditLogAdmin.vue` 的样式基础，但按项目维度精简（无操作者筛选框，仅展示）

## 6. 不做的事（范围边界）

- 不新建日志表、不双写、不改 audit_log 保留期（24 个月足够项目追溯）
- 不记录读操作（浏览/查询不进流水线，只记写操作）
- 不展示系统级操作（登录/登出、配置变更、备份等不属于项目流水线）
- 旧数据不迁移（方案 A 天然兼容：节点/任务归属由 join 现算）

## 7. 兼容性与验证

- 表结构零变更，无 alembic 迁移，无数据丢失风险（符合 CLAUDE.md 数据库兼容红线）
- 验证：本地真实 PostgreSQL（pmtestdb）冒烟——创建/编辑项目、改节点计划时间、加周目标、流转节点后，调流水线接口核对记录与 summary 文案；成员/非成员权限各验一次
