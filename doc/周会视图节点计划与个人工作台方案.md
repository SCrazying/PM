# 周会视图、节点计划与个人工作台方案

## 1. 需求目标

本次迭代围绕项目执行过程中的三个关键问题进行补齐：

1. 周会视图默认需要更接近 Excel 项目台账，先以项目列表展示，全部项目默认折叠；展开单个项目后查看任务、每日进展和风险等详细信息。
2. 新建项目选择 TR 节点时，只维护每个节点的计划完成时间，并在节点超过计划完成时间且尚未完成时显示预警。
3. 进展记录目前只能新增，补充进展编辑能力；同时增强个人工作台，使用户能够快速看到参与项目、节点状态、近期进展和待处理事项。

## 2. 交互方案

### 2.1 周会视图

- 默认采用“按项目”的 Excel 风格列表，列出项目型号、项目名称、项目角色、当前节点、周目标、任务概况和项目健康状态。
- 页面首次进入时不展开任何项目。
- 每一行通过展开入口查看该项目的详细周报，包括任务列表、每日进展和风险。
- 节点已超期时，在当前节点列显示预警标识；项目详细视图同时展示节点计划时间和超期提示。
- 保留按人查看和项目台账导出能力。

### 2.2 项目创建与节点计划

- 创建项目选择模板节点后，为每个已选节点显示计划完成日期。
- 节点计划完成日期必填。
- 创建请求将节点计划写入项目节点实例；编辑项目暂不改变已创建节点的计划，避免影响历史执行数据。
- 编辑项目可以修改已创建节点的计划完成日期，不能修改节点归属和历史实际完成日期。
- 超期判定规则：当前日期晚于节点计划完成日期，且节点状态不是已完成/已通过。
- 在项目详情、周会列表和个人工作台中显示超期预警。

### 2.3 进展编辑

- 项目详情的进展时间线为当前用户自己的记录提供“编辑”入口，管理员可以编辑全部记录。
- 编辑范围包含今日进展、明日计划和风险；进展日期、所属节点和作者只读。
- 保存后刷新时间线并保留现有权限校验。
- 个人工作台增加“最近进展”列表，同样支持编辑当前用户的进展记录。

### 2.4 个人工作台

- 保留今日进展填报和我的任务。
- 项目卡片补充当前节点、参与角色和节点计划完成日期；节点超期时显示预警。
- 增加近期进展列表，直接展示项目、日期、节点和进展摘要，并提供编辑入口。
- 后端工作台接口一次返回项目摘要、待办任务和近期进展，避免页面重复请求。

## 3. 数据与接口设计

### 3.1 创建项目请求

在创建项目请求中增加 `node_plans`：

```json
[
  {
    "template_node_id": 1,
    "planned_end": "2026-08-10"
  }
]
```

服务端根据模板节点生成项目节点实例时写入 `planned_end`；未选中的模板节点不生成实例。历史客户端仍可提交 `planned_start`，服务端会兼容接收，但新页面不再要求填写。

编辑项目请求增加 `node_deadlines`：

```json
[
  { "project_node_id": 101, "planned_end": "2026-08-10" }
]
```

### 3.2 节点输出

项目节点输出增加 `overdue` 字段，前端无需自行复制超期判定规则。周报和工作台项目摘要同步返回当前节点计划完成日期及超期状态。

### 3.3 工作台输出

`GET /progress/my-todo` 返回：

- `projects`：参与项目、参与角色、当前节点、计划完成日期和超期状态；
- `tasks`：当前用户待办任务；
- `recent_progress`：当前用户最近进展记录，包含编辑所需的记录 ID 和文本字段。

## 4. 实施与验证

实施顺序：

1. 先补充创建/编辑请求和节点截止时间逻辑，不新增数据库字段。
2. 增加节点超期字段及周会/详情/工作台展示。
3. 将周会项目视图改为默认折叠的列表展开结构。
4. 增加项目详情和工作台进展编辑。
5. 完成前端构建、Python 编译和关键数据转换校验。

兼容性原则：已有项目的 `planned_start` / `planned_end` 字段保留不变；已有项目只展示和编辑 `planned_end`，空截止时间不判定为超期；已有进展数据不迁移，继续按原权限规则编辑。
