# PM-System 部署手册

| 文档版本 | V1.0 |
|---|---|
| 适用 | 内网单机部署（≤50 用户） |
| 技术栈 | Vue3 + FastAPI + PostgreSQL |

> 提供**两种部署方式**：方式一 Docker（有 Docker 时首选）、方式二 离线/原生（内网无 Docker）。两种方式运行同一套应用。

---

## 0. 前置准备（在**能上网**的机器上做一次）

准备离线物料（两种方式都需要，除非目标机能联网）：

```bash
# 后端依赖离线 wheels + 前端构建产物 + 可选基础镜像
pip download -r backend/requirements.txt -d backend/wheels/
(cd frontend && npm install && npm run build)
```

打包以下内容拷贝到内网服务器：
```
backend/  frontend/dist/  db/  deploy/  docker-compose.yml  README.md
```

> **安全提醒**：`db/seed.sql` 的管理员密码哈希是占位符，部署前替换（生成命令见 seed.sql 注释）；`backend/.env` 务必改 `JWT_SECRET`。

## 方式一：Docker 部署（首选）

### 适用
目标机装有 Docker + docker compose。

### 步骤
```bash
# 1. 内网无法访问 Docker Hub 时，先导入基础镜像
docker load -i deploy/offline/images/base-images.tar

# 2. 配置后端环境变量
cp backend/.env.example backend/.env
#    编辑：JWT_SECRET / POSTGRES 密码 / AI_BASE_URL / AI_API_KEY

# 3. （可选）设置数据库密码
export POSTGRES_USER=pm
export POSTGRES_PASSWORD=你的强密码
export POSTGRES_DB=pm_system

# 4. 放置 TLS 证书到 deploy/nginx/certs/（server.crt / server.key）
#    自签：openssl req -x509 -nodes -days 825 -newkey rsa:2048 \
#      -keyout deploy/nginx/certs/server.key -out deploy/nginx/certs/server.crt

# 5. 启动
docker compose up -d

# 6. 查看状态 / 日志
docker compose ps
docker compose logs -f backend
```

后端启动时会自动执行 `alembic upgrade head`（建表）与 `python -m app.seed`（种子数据）。

默认内网 HTTP 访问：`http://<服务器IP>/`。例如服务器 IP 为 `10.10.98.10` 时，组内同事访问 `http://10.10.98.10/`。

若启用 TLS：将 `deploy/nginx/nginx-tls.conf` 作为 Nginx 配置，并放置 `server.crt/server.key`，再访问 `https://10.10.98.10/`。
请在服务器防火墙放行 TCP 80；启用 TLS 时同时放行 TCP 443。

### 备份
```bash
docker compose exec db pg_dump -U pm pm_system | gzip > backup_$(date +%F).sql.gz
```

## 方式二：离线 / 原生部署（内网无 Docker）

### 适用
目标机无 Docker，直接装在本机/内网服务器。**当前提供 Windows 数据库初始化脚本**（`deploy/scripts/init_db.ps1`），Linux 可参照移植。

### 依赖
- PostgreSQL 14+、Python（含后端依赖）、Nginx（可选，前后端同端口时用反向代理）

### Windows 数据库初始化（一键）
```powershell
# 前置：已安装 PostgreSQL，记下 postgres 超级用户密码
powershell -ExecutionPolicy Bypass -File deploy\scripts\init_db.ps1 -PgPassword "<postgres密码>"
```
脚本自动完成（幂等，可重复执行）：
1. 创建应用用户 `pm` 与数据库 `pm_system`（已存在则跳过）
2. 自动补全 `backend/.env` 的 `DATABASE_URL`
3. 执行 Alembic 迁移建表（18 张表 + 索引）
4. 写入种子数据（内置 TR1~TR6 模板、初始管理员、默认配置）

```powershell
# 可选参数
#   -AppPassword "新密码"    指定应用用户 pm 的密码（默认 pm123）
#   -DbName "库名"          指定数据库名
#   -Psql "C:\...\psql.exe" 指定 psql 路径（自动探测常见安装目录）
```

### 后续（前端 + 常驻）
1. 构建前端 `frontend\dist` 拷到站点目录。
2. 配置 Nginx：`/ → 前端静态`、`/api/* → 127.0.0.1:8001`。
3. 用 NSSM / 任务计划程序常驻后端：`uvicorn app.main:app --host 127.0.0.1 --port 8001`。
4. 健康检查：`curl http://127.0.0.1:8001/health`。

### 备份与恢复（通用 pg_dump 命令）
```powershell
# 手动备份
pg_dump -U pm pm_system | Out-File -Encoding utf8 db_$(Get-Date -Format yyyyMMdd).sql
# 或直接输出到文件
pg_dump -U pm -h 127.0.0.1 pm_system -f db_backup.sql

# 恢复（先建空库）
createdb -U pm pm_system_restore
psql -U pm -h 127.0.0.1 -d pm_system_restore -f db_backup.sql
```
> 建议用系统"任务计划程序"每日定时执行 `pg_dump`；附件目录单独增量备份。也可在系统管理页手动触发备份（后端已提供 `/backup` 接口）。

## 环境变量（backend/.env）
| 变量 | 说明 | 默认 |
|---|---|---|
| DATABASE_URL | 数据库连接串 | postgresql+psycopg2://pm:pm123@127.0.0.1:5432/pm_system |
| JWT_SECRET | JWT 密钥（**必改**） | change-me-in-prod |
| JWT_ACCESS_TTL_MIN | access token 有效期（分） | 120 |
| JWT_REFRESH_TTL_DAY | refresh token 有效期（天） | 7 |
| LOGIN_MAX_FAIL / LOCK_MINUTES | 登录锁定 | 5 / 15 |
| AI_BASE_URL / AI_API_KEY / AI_MODEL | OpenAI 兼容 API | 空 / 空 / gpt-4o-mini |
| UPLOAD_DIR / BACKUP_DIR | 附件/备份目录 | ./data/... |
| CORS_ORIGINS | 允许的前端源（同源部署留空） | 空 |

## 首次使用
1. 用 `admin` / 部署时设置的密码登录。
2. 系统管理 → 配置 AI（base_url/api_key/model）、周界、提醒规则。
3. 系统管理 → 用户管理，批量建组内成员。
4. （可选）系统管理 → Excel 导入，迁入历史项目。
5. 开始新建项目，勾选 TR 节点并填写每个节点的计划完成日期。
6. 周会视图选择周次，点击“导出项目台账”，下载固定 7 列格式的 xlsx（列宽、换行、冻结表头已预设）。

## 故障排查
| 现象 | 排查 |
|---|---|
| 502 / 无法访问 | `systemctl status pm-system` / `docker compose logs backend`；确认 8000 端口监听 |
| 登录报错 | 数据库是否建表（`alembic upgrade head`）、种子是否执行（`python -m app.seed`） |
| AI 总结失败 | AI_BASE_URL/AI_API_KEY 是否配置；后端能否访问该 API；会自动降级为模板汇总 |
| 附件上传失败 | UPLOAD_DIR 权限、大小白名单（默认 50MB） |
