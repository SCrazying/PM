# 内网部署与节点截止时间兼容升级方案

## 1. 组内访问结论

若应用部署在 `10.10.98.10`，组内同事可以通过以下地址访问：

- Docker 内网默认 HTTP：`http://10.10.98.10/`
- 配置 TLS 证书后：`https://10.10.98.10/`

能否访问还取决于服务器防火墙是否放行 TCP 80（HTTP）或 TCP 443（HTTPS），以及同事电脑与 `10.10.98.10` 网络可达。前端开发服务器如临时使用 Vite，则通过 `http://10.10.98.10:5173/` 访问，并要求启动监听 `0.0.0.0`。

本次部署修正 Docker Nginx 到后端的容器端口：后端容器实际监听 8000，Nginx 反向代理也使用 `backend:8000`。默认内网配置不强制依赖不存在的 TLS 证书，避免 Nginx 因证书文件缺失无法启动；需要 HTTPS 时再放置证书并启用 TLS 配置。

## 2. 节点截止时间

- 新建项目选择节点后，只填写每个节点的计划完成日期 `planned_end`。
- 不再要求填写计划开始日期。
- 已有数据库中的 `planned_start` 字段保留，旧接口仍可携带该字段；新页面不再依赖它。
- 编辑项目可以修改已创建节点的计划完成日期。
- 超期规则保持不变：`status != 'passed' AND planned_end < today`。

## 3. 编辑项目修复

编辑项目表单不再加载只有创建时才需要的节点模板，避免模板接口权限或失败阻断编辑弹窗。

项目编辑请求通过 `node_deadlines` 更新项目节点截止日期，并由服务端校验节点确实属于当前项目；项目名称、负责人、日期、角色和节点截止日期一次提交，保持原有事务边界。

同时增加只读用户选项接口供项目成员/角色选择使用，用户管理增删改仍保持管理员权限，避免普通项目负责人打开编辑页面时因调用管理员用户接口而失败。

## 4. 数据库兼容性

本次升级不新增、不删除、不修改数据库字段，不生成破坏性迁移。既有 `project_node.planned_start` 和 `project_node.planned_end` 字段继续使用，旧项目数据无需迁移。

部署启动仍执行 `alembic upgrade head`，只会补齐尚未执行的历史迁移；建议升级前保留一次 PostgreSQL 备份，升级后检查 `/health`、项目编辑和节点截止日期。

## 5. 验证清单

1. 在 `10.10.98.10` 上确认 Docker、Nginx、后端容器均为运行状态。
2. 服务器执行 `curl http://127.0.0.1/health`。
3. 组内电脑执行 `curl http://10.10.98.10/health` 或浏览器打开前端地址。
4. 新建项目只填写节点截止日期并保存。
5. 打开已有项目编辑，修改节点截止日期并保存，刷新后确认日期保留。
6. 检查旧项目、旧 Excel 导入和已有角色数据仍可正常读取。
