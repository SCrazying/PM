# 项目角色管理与 Excel 导入导出方案

## 1. 需求范围

项目角色固定包含以下四类：

| 角色 | 选择方式 | 数据约束 |
|---|---|---|
| SE | 单选 | 一个项目最多 1 名用户 |
| TPM | 单选 | 一个项目最多 1 名用户 |
| TL/FO | 多选 | 一个项目可选择多名用户 |
| CodeReview | 多选 | 一个项目可选择多名用户 |

角色选择需要同时出现在新建项目和编辑项目弹窗中。角色不是项目负责人字段的替代品，负责人仍由原有 `owner_id` 管理。

## 2. 数据设计

现有 `project_member` 继续表示“用户参与项目”，用于任务指派、进展填报和旧数据兼容；新增 `project_role_assignment` 表表示“项目角色分配”：

| 字段 | 说明 |
|---|---|
| `project_id` | 项目 ID |
| `role` | `SE` / `TPM` / `TL/FO` / `CodeReview` |
| `user_id` | 被分配角色的用户 ID |

对 `(project_id, role, user_id)` 建立唯一约束。角色分配用户自动进入 `project_member`，但不改变现有项目成员的投入状态。角色分配表作为四类固定角色的唯一数据源，旧项目仍可从 `project_member.project_role` 读取同名角色作为兼容兜底。

## 3. API 约定

新建和编辑项目请求增加 `role_assignments`：

```json
{
  "role_assignments": {
    "SE": [101],
    "TPM": [102],
    "TL/FO": [103, 104, 105],
    "CodeReview": [106, 107]
  }
}
```

前端单选控件也转换为长度为 0 或 1 的数组，后端统一校验：未知角色拒绝，SE/TPM 超过 1 人拒绝，用户不存在拒绝。编辑时传入完整角色集合，后端以本次集合替换旧分配，清空控件即可解除角色。

项目详情响应增加相同结构的 `role_assignments`，供编辑弹窗回填。

## 4. 前端交互

- `SE`、`TPM` 使用可搜索单选下拉框，可清空。
- `TL/FO`、`CodeReview` 使用可搜索多选下拉框，支持标签折叠和清空。
- 新建时四个角色默认为空；编辑时按项目详情回填。
- 提交项目时角色与项目基础信息一起提交，避免先保存项目再逐个补角色造成中间状态。

## 5. Excel 导出格式

保持现有项目台账 7 列及按成员一行的兼容格式。每个项目的“项目角色”列使用同一份项目级角色摘要，单元格启用自动换行，格式为：

```text
SE: XXXX
TPM: XXXX
TL/FO: AAA、BBB、CCC
CodeReview: DDD、EEE
```

角色顺序固定为 `SE`、`TPM`、`TL/FO`、`CodeReview`；没有用户的角色不输出空行。导出同时增加 `负责人: 用户名` 行，确保负责人在导入时不丢失。每个项目的重复成员行在导入时按“项目 + 角色 + 用户”去重。

角色摘要以角色分配表为准；对尚未建立角色分配记录的旧项目，回退读取 `project_member.project_role` 中的四类固定角色。单元格行高按角色摘要和本周任务内容的最大行数计算。

## 6. Excel 导入规则

导入预览识别“项目角色”单元格中的角色行，兼容：

- 实际 Excel 换行（CRLF/LF）；
- 字面量 `\\n`、`\\N`；
- 中英文冒号；
- 用户分隔符 `、`、`,`、`，`、`;`、`；`。

角色标签按大小写和空格做兼容匹配，标准化为四个固定角色。匹配到系统用户后写入角色分配；未匹配用户保留预览告警，不写入无效用户。重复导出行不产生重复角色分配。旧格式中独立的“成员/姓名/人员”列继续按原规则导入。

导入确认仍采用现有 preview/confirm 两步流程：preview 只解析和提示，confirm 在同一事务内写入项目、成员、角色、节点、周目标和任务。

## 7. 开发与验收

1. 增加 ORM 模型、初始化 SQL 和 Alembic 增量迁移。
2. 增加项目创建/编辑的角色请求校验及项目详情回填。
3. 增加角色摘要导出和结构化导入解析。
4. 前端构建通过，后端模块可导入。
5. 用包含单人角色、多人角色、空角色、重复导出行和换行文本的样例验证导入预览及导出工作簿内容。
